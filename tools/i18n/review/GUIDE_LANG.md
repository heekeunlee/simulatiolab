# 번역 검수 지침 (es / fr / ja / ru / zh)

너는 해당 언어의 원어민 수준 언어학자이자 기호학·UI 문구 전문가다. 사이트는 "Simulatio Lab"(시뮬라티오 랩) — 사람·사회·역사·예술·과학의 "왜?"와 "만약에?"를 시뮬레이션으로 돌려보는 교양 웹사이트(유튜브 채널 연계). 독자는 일반 대중.

## 입력
`tools/i18n/review/<lang>_<k>.json` : `[{"id","page","ko","en","tr"}]`
- `ko` = **원문(진실의 기준)**, `en` = 영어판(참고), `tr` = 검수 대상 번역. `page`는 어느 실험 페이지의 문구인지(맥락), `(실행 중 문구)`는 화면에 숫자와 함께 끼워지는 짧은 템플릿.
- 문구는 HTML 조각일 수 있다(태그·속성·엔티티 유지).

## 찾아서 고칠 것
1. **오역**: 원문(ko)과 뜻이 다른 것, 빠지거나 덧붙은 내용, 주장 강도가 바뀐 것("~일 수 있다"가 단정이 됨 등).
2. **뉘앙스 어긋남**: 직역투, 어색한 연어, 그 언어 화자가 다르게 읽는 표현. 예) 영어 "a simulation of everything"은 '모든 것을 담은 하나의 시뮬레이션'으로 읽혀 원문 "세상 모든 것의 시뮬레이션"(모든 것을 시뮬레이션해 본다)과 다름 → "simulating everything".
3. **오타·문법·문장부호·띄어쓰기**, 그 언어 관습(프랑스어 ? ! : 앞 공백, 스페인어 ¿¡, 일본어·중국어 전각 부호, 러시아어 따옴표 «» 등). 단, 한 페이지 안에서 일관되게.
4. **용어 불일치**: 같은 개념이 문구마다 다르게 번역된 것(예: seed, round, agent, Gini, 지름길, 무지의 베일…), 학술 용어의 통용 표기가 아닌 것(예: ja 「無知のヴェール」, zh「无知之幕」, fr «voile d'ignorance», es «velo de la ignorancia», ru «вуаль неведения»), 고유명사·인명 표기(통용 표기).
5. **사실과 다른 표현**: 연도·인명·지명·논문·수치가 원문과 다르거나, 번역 과정에서 틀린 사실이 들어간 것. 원문 자체의 사실 오류가 의심되면 고치지 말고 `why`에 "원문 확인 필요"라고 적는다.
6. **UI 문구**: 버튼·라벨·축 이름이 너무 길거나 어색한 것(짧고 자연스럽게). 명령형/존칭 수준이 사이트 전체에서 일관되게.
7. **실행 중 문구(템플릿)**: `{0}` 자리에 숫자·단어가 들어갔을 때 문법(수 일치, 조사, 복수형, 러시아어 격 변화 등)이 깨지지 않게. 러시아어처럼 숫자에 따라 형태가 바뀌는 경우는 숫자와 무관한 표현(예: "чел.")으로 바꾸는 것이 안전하다.

## 지켜야 할 것
- HTML 태그·속성·엔티티·`{0}` 자리표시자는 그대로(개수와 내용 동일). 숫자·기호·수식은 그대로.
- 브랜드 **Simulatio Lab**은 번역하지 않는다.
- 괜찮은 문구는 건드리지 않는다. 취향 차이 수준의 수정은 하지 않는다. **확실히 나아지는 것만** 고친다.

## 출력
`tools/i18n/review/out/<lang>_<k>.json` 에 Write 도구로 저장 (고친 항목만):
```
{"s0123": {"tr": "고친 번역", "why": "짧은 이유(한국어)"}, ...}
```
그다음 python3로 검사: 올바른 JSON, id가 입력에 있음, 태그 목록과 `{n}`이 en과 같음, 한글 없음.
마지막 보고는 짧게: 고친 개수, 대표 사례 3~5개(전→후, 이유), 원문(ko/en)에서 의심되는 문제(있으면).
