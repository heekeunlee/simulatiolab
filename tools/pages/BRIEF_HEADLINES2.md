# 결과 해석 헤드라인 2~3개 + 통찰 (2026-10-13, 2차)

각 실험 페이지의 "이 결과가 말하는 것 / 말하지 않는 것" 상자에 **헤드라인을 2~3개(의미 부여할 게 정말 없으면 1개)** 만든다. 1차 문구(`tools/pages/headlines/<slug>.json`, 한 문장씩)는 결과를 되풀이하는 수준이었다. 이번엔 **결과를 바탕으로 유추할 수 있는 통찰(인사이트)**을 보여 주는 문구여야 한다.

## 입력
- 기존 파일 `tools/pages/headlines/<slug>.json` (1차 헤드라인 — 첫 줄 후보로 다듬어 써도 된다)
- 페이지 `site/experiments/<slug>/index.html` 의 `<div class="callout ...">` 안 `.cfull` 문단(긴 설명, 한국어 본문과 `data-en` 영어). 아래 명령으로 보면 편하다:
`python3 - <<'P'
import re,html
s=open('site/experiments/<slug>/index.html',encoding='utf-8').read()
for m in re.finditer(r'<p class="cfull" data-en="([^"]*)">(.*?)</p>',s,re.S): print(html.unescape(re.sub('<[^>]+>','',m.group(2)))); print('EN:',html.unescape(re.sub('<[^>]+>','',html.unescape(m.group(1))))); print()
P`
- 필요하면 같은 페이지의 "모델은 이렇게 움직입니다"·이론 칸(`.small` 목록)도 읽어 통찰의 근거로 삼는다.

## 출력 (UTF-8, 덮어쓰기)
`tools/pages/headlines/<slug>.json`:
`{"says_ko": ["...", "..."], "says_en": ["...", "..."], "not_ko": ["...", "..."], "not_en": ["...", "..."]}`
- 네 값 모두 **문자열 배열**. 한국어와 영어 배열은 **같은 개수·같은 순서**(1:1 대응).
- 말하는 것: 2~3개. 1번 = 핵심 결과(숫자가 있으면 원문의 숫자), 2~3번 = **통찰**(이 결과가 일반적으로 무엇을 시사하는가, 우리가 세상을 볼 때 어떤 관점이 바뀌는가). 말하지 않는 것: 1~3개. 가장 중요한 한계·흔한 오해 → 그다음 "그렇다면 실제로 확인하려면 무엇이 더 필요한가"처럼 건설적인 한 줄.
- 한 줄은 한국어 55자 안팎(최대 70자) · 영어 110자 안팎(최대 140자), 한 문장. 쉬운 말(해요체/합니다체는 원문에 맞춰 통일). 라벨("말하는 것:")과 HTML 태그는 쓰지 않는다.
- 예(새치기): 말하는 것 ① "새치기는 처음엔 퍼지지만, 응징하는 사람이 충분하면 다시 사라져요." ② "질서는 저절로 지켜지는 게 아니라, 누군가 비용을 치르며 지켜 내는 결과예요." ③ "규칙 지킴을 바꾸려면 새치기를 막는 사람의 비용부터 살펴볼 만해요." / 말하지 않는 것 ① "현실의 줄 서기가 이렇게 단순하다는 뜻은 아니에요." ② "눈총의 비용·효과는 이 모델이 정한 값이라 실제 크기는 따로 확인해야 해요."

## 규칙 (정직성이 우선)
- **통찰은 결과에서 논리적으로 따라 나와야 한다.** 원문이 말하지 않은 새 사실·수치·연구 결과를 만들지 않는다. 시뮬레이션이 모델의 가정에서 나온 것이면 "이 모델에서는/가정하면" 같은 단서를 살리거나, "…일 수 있어요/…살펴볼 만해요"로 강도를 낮춘다. 원문이 이론과 안 맞는다·재현 안 됐다고 한 것은 그대로 반영한다.
- 의학·투자·교육·육아·전쟁 소재는 **처방·조언·예측을 하지 않는다**(원문의 면책 취지 유지). 통찰은 "구조가 이렇게 돌아간다" 수준에서.
- 거창한 일반화·교훈 강요·훈계 금지. 사람·집단을 탓하지 않는다.
- 억지로 3개를 채우지 말 것: 통찰이 없으면 1~2개로 끝낸다.

## 마무리
`python3 -c "import json,glob;[json.load(open(f)) for f in glob.glob('tools/pages/headlines/<slug>.json')]"`로 확인하고, ko/en 개수가 같은지 확인한다. 한 줄로만 보고(만든 개수, 1개짜리 상자가 있으면 어느 slug인지).
