# 브라에스의 역설(braess)에 "지도 앱 위의 3D 도시" 보기 추가 (2026-10-15)

운영자 요청: 지금 ① 화면(마름모 꼭짓점 + 대각선 지름길)은 구조는 맞지만 단순하다. **3D 도시 도로망**을 **지도 앱 느낌의 바닥** 위에 올려 고급스럽게 보여 준다. 시뮬레이션(`site/experiments/braess/sim.js`)·숫자·validate 결과는 **바꾸지 않는다**. 3D는 같은 상태만 읽고 새 계산·새 수치를 만들지 않는다.

먼저 읽을 것: `BRIEF_3D5.md`(3D 공통 요구), `BRIEF_ART6.md` 규칙 5~9, `site/lab3d.js`·`lazy3d.js`, 3D 참고 구현 `site/experiments/depopulation/app3d.js`(지도형 풍경, 낮/밤, 인스턴스드 메시, 도로·점 흐름)와 `ventilation/app3d.js`, 생성기 `tools/pages/depopulation.py`의 `three=True` 섹션, 그리고 `tools/pages/braess.py`·`site/experiments/braess/{app.js,sim.js}`. 특정 회사 지도 앱·디자인·글꼴·심볼을 쓰거나 언급하지 말 것(일반적인 "연한 지도 스타일"로 직접 그린다).

## 설계
- **바닥 = 지도 앱 느낌의 평면**: 연한 베이지/회백 땅, 옅은 초록 공원 몇 곳, 연한 하늘색 강 한 줄기, 격자 블록(아주 옅은 선). 모두 단순한 평면 메시·색으로(텍스처 이미지 금지, 인스턴스드 상자로 낮은 건물 수십~백여 채: 흰색·연회색 지붕, 그림자 약하게). 밝은 배경.
- **도로망 = 모델 그대로 네 꼭짓점**: 출발(왼쪽), 도착(오른쪽), A(위), B(아래)를 도시 안 네 지점으로 두고 **곡선 또는 완만한 꺾임의 도로 4개**(출발→A, A→도착, 출발→B, B→도착)를 지도 위 도로처럼 그린다(흰 도로 + 연회색 테두리, 막히는 길 2개는 조금 넓은 도로). 꼭짓점에는 작은 표지(출발: 집 몇 채 동네, 도착: 사무 빌딩 몇 채, A·B: 교차로 표지). 지름길 A→B는 **강을 건너는 다리**: 닫혀 있으면 다리 상판이 들려 있거나(도개교) 반투명 점선, "지름길 열기"를 누르면 상판이 내려오며 연결된다(애니메이션 1초 안팎, 상태는 `sim`의 열림 여부만 읽음).
- **차량**: 인스턴스드 작은 상자(차) 수백~천 대 정도(운전자 수 n에 비례하되 PC 최대 ~900, 휴대폰 ~350으로 상한, 비율 유지). 각 차는 **지금 라운드의 세 길 선택 비율**(`sim.shares` 또는 운전자별 길 배열)에 따라 길에 배치되어 **그 길의 현재 걸리는 시간에 반비례하는 속도**로 움직인다(막히면 느리고 줄지어 섬 — 이는 상태의 시각화일 뿐 새 계산이 아님을 페이지에 한 줄로 밝힌다). 도로 색은 2D와 같은 규칙(초록 빠름 → 빨강 느림, 2D의 색 함수를 재사용).
- **운전자 한 명 따라가기**: 임의의 운전자 한 명(판마다 고정, `seed`로)을 **노란 차**로 표시하고, 통계 카드에 "이 운전자의 출근 시간: NN분"(그 운전자가 고른 길의 현재 시간 = sim에서 읽음)을 보여 준다. 길을 바꾸면 노란 차가 다음 바퀴부터 새 길로 간다.
- **시계 바늘**: 3D 캔버스 오른쪽 위 작은 **원형 시계**(HTML/CSS 또는 2D 캔버스 오버레이, 3D 밖) — 바늘이 평균 출근 시간(분)을 가리키고 65→80처럼 늘어날 때 바늘이 뒤로 돈다. 눈금 0~120분, 숫자 함께 표시. 값은 app.js가 이미 계산한 평균(현재 라운드)만 사용.
- **낮/밤 선택**(기본 낮): 밤에는 도로가 어둡고 차 헤드라이트(작은 밝은 점/emissive)만 보임. 가볍게(포인트 라이트 다수 금지).
- 카메라: 비스듬히 내려다보는 지도 시점, 자동 느린 회전은 **기본 끔**(지도는 방향이 고정돼야 읽기 쉬움; 켜기 옵션은 둬도 됨), 드래그 회전·휠/핀치 확대. 휴대폰 390px 부드럽게, `?thumb=1` 예외 없이.
- 섹션 배치: 새 3D를 **① 맨 위**(`three=True`, `id='c-3d'`, `data-thumb` 이동 → 썸네일은 3D 장면), 기존 2D 마름모는 바로 아래 **"② 노선도로 보기"**(구조 설명용, 그대로 둠, 크기 그대로여도 됨). 이후 섹션 번호 밀기. 지름길 열기 버튼(`#toggle`)은 3D 아래에 두고 2D와 같은 버튼이 두 개가 되면 혼란이니 하나만(3D 아래) 두고 2D 섹션 설명에 "위 버튼으로" 안내.
- 범례(캔버스 아래 한 줄, 모양 2~3종): 도로 색(빠름/느림), 노란 차 = 따라가는 운전자, 다리 = 지름길. 힌트(`hint3d`): "같은 결과를 지도 위 도시로 본 것, 차의 수와 움직임은 선택 비율과 걸리는 시간을 보여 주는 표시일 뿐 운전자 개개인의 실제 경로 계산이 아님", 드래그·확대 안내.
- 한국어는 `T('ko','en')`, 실행 중 문구는 `dyn_braess.py`(없으면 만들고, 다른 실험과 같은 한국어 키에 다른 영어를 붙이지 않게 주의). 번역은 호출한 쪽이 한다. `build_dyn.py` 실행·공용 파일 수정·커밋·푸시 금지. 임시 파일은 scratchpad에 braess3d- 이름으로.

## 검증(모두 통과 후 보고)
`export NODE_PATH=~/.simlab-tools/node_modules`; `python3 tools/pages/braess.py`; `node tools/validate-braess.js`(있으면, 출력 변화 없음); `node tools/browser/check.js braess ko,en 3500`(en은 build_dyn 없이 어려우면 ko + 콘솔 오류만 확인하고 알림); `node tools/browser/make_thumbs.js braess`; Playwright로 PC·휴대폰 `#c-3d` 캡처를 **직접 열어** 지름길 닫힘/열림(다리), 차 줄지어 섬, 노란 차, 시계, 밤 모드를 확인. "차가 몰려 막히는 것과 다리가 열리는 것이 한눈에 보이는지"를 엄격히 판단하고 부족하면 고친다. 보고(한국어, 짧게): 바뀐 파일, 시각 요소, 성능, 새 문구 목록, 막힌 점.
